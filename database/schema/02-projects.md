# Group 2 — Integrations & Projects

`integrations` · `projects`

## Purpose

The connection to external CI/CD platforms, and the repositories being monitored.

## Key decisions

**No separate `repositories` table.** A project maps 1:1 to a repository in every
provider we support. The original sketch listed it; folding it into `projects` removes a
join from every hot query. Revisit only if monorepo-multi-pipeline support becomes real.

**`integrations.credentials`** is `encrypted:array` cast, in `$hidden`, and never
returned by any endpoint. A test asserts this across every list endpoint — a leaked
token here compromises the user's entire CI platform.

**`webhook_secret`** is generated by PipeMind and given to the provider, not the reverse.
Signature verification uses `hash_equals`, never `==`.

## Denormalised counters on `projects`

`pipelines_count`, `success_rate`, `failures_today`, `last_pipeline_id`,
`last_pipeline_at`, `health_status`.

The workspace grid renders N project cards, each needing four aggregates over a
forever-growing table. That is 4×N aggregate queries per page load. These columns are
refreshed on pipeline completion and on a 5-minute schedule.

**`health_status` is derived, and deliberately different from `success_rate`:**

| Status | Rule |
|---|---|
| `failing` | last pipeline failed |
| `degraded` | success_rate < 90% |
| `healthy` | otherwise |
| `unknown` | no pipelines yet |

Success rate is a 30-day average; health is *right now*. A project at 98% whose last
pipeline just failed must not render green.

## Gotchas

- `UNIQUE(integration_id, external_id)` prevents importing the same remote project twice.
- `analyze_on_branches` defaults to `["*"]`. Teams with many feature branches should
  narrow it — auto-analysing every branch is the largest avoidable cost in the system.
- `ai_provider_id` and `last_pipeline_id` are FKs added in a **late migration**: they
  reference tables created after `projects`, and adding them inline creates a circular
  dependency that no migration order can satisfy.
